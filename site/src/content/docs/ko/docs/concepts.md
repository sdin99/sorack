sorack은 몇 가지 기본 요소로 홈랩을 모델링합니다. 이 페이지에서 각 요소를 설명합니다.

## 2축 노드 모델

모든 노드는 서로 독립적인 두 축을 가집니다.

- **인프라 타입**: `host`, `vm`, `container`, `k8s_cluster`, `k8s_namespace`,
  `router` 등. 노드가 무엇인지를 나타내며, [정해진 목록](/ko/docs/nodes/)에서
  고릅니다. 상세 패널에 어떤 필드를 보여 줄지 타입이 정하므로, sorack이 모르는 타입은
  오류 대신 빈 패널로 표시됩니다.
- 0개 이상의 **소프트웨어 부착**: Proxmox VE, PostgreSQL, Jellyfin 등. 노드에서
  무엇이 실행되는지를 나타냅니다.

두 축의 상세 필드와 모니터링 슬롯은 함께 표시됩니다. 예를 들어 Proxmox 호스트는
인프라 타입의 호스트 필드와 소프트웨어 부착의 PVE 필드를 한 패널에 보여 줍니다.

## 토폴로지 + 타입이 있는 엣지

인벤토리가 곧 그래프입니다. 캔버스에서 노드를 직접 만들고, 이름을 바꾸고, 옮기고,
연결하며, 노드 사이에 **타입이 있는 엣지**를 그립니다. 그래프 배치는
[dagre](https://github.com/dagrejs/dagre)가 자동으로 합니다. 이름을 바꿔도 배치는
그대로이고, 노드를 옮기거나 엣지를 그리면 그래프가 다시 배치됩니다.

## 축별 모니터링

각 축에는 프로브가 하나씩 있습니다. 예를 들어 인프라 축에서는 도달성 프로브를,
소프트웨어 축에서는 Proxmox API 프로브를 동시에 실행할 수 있습니다.

두 축 이상이 보고하면 **StatusLine**이 노드 상태를 정할 축 하나를 고르고, 축을
바꿔 볼 수 있는 버튼 줄을 보여 줍니다. 수집기는 프로브가 없는 노드를 바꾸지 않으므로
수동 상태와 자동 상태가 충돌하지 않습니다.

### “모니터링 안 됨”과 unknown

화면은 두 상태를 다르게 표시합니다.

| 표시 | 뜻 |
| --- | --- |
| **모니터링 안 됨** | 어느 축에도 프로브가 설정되지 않았습니다. |
| `unknown` | 프로브가 실행됐지만 판정하지 못했습니다. 예: 타임아웃, 403, 작업 실행 기록이 정리된 경우. |

**모니터링 안 됨**으로 표시되는 노드는 모니터링의 빈 곳입니다. `unknown`으로
표시되는 노드는 프로브를 확인해야 합니다.

sorack은 `monitored` 값을 노드의 프로브 설정에서 계산하며 저장하지 않으므로 값이 항상
최신입니다. 동기화가 일부러 노드를 모니터링하지 않는다면
[`meta.probeSkipped`](/ko/docs/nodes/#동기화가-쓰는-키) 값에 이유를 남길 수 있습니다.

:::note
상태는 수집기만 설정합니다. 노드를 손으로 초록색으로 바꿀 수는 없으며, 프로브가 없는
노드는 **모니터링 안 됨**으로 표시됩니다.
:::

## 점검 모드

노드를 점검 중으로 표시하면 수집기가 그 노드와 하위 트리를 건너뜁니다. 계획된 중단이
장애로 표시되지 않고, 노드는 오류 대신 점검 중 상태로 표시됩니다.

## 런북

런북은 노드에 연결된 마크다운 문서입니다. 앱이 런북을 렌더링하며, 분할 화면 편집기,
`[[node:…]]`와 `[[runbook:…]]` 링크, 선택적 git 동기화, 파일 첨부를 지원합니다.
런북에서는 연결된 노드를 볼 수 있고, 노드 상세 패널에서는 그 노드의 런북으로 갈 수
있습니다.
