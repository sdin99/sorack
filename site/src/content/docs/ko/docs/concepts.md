sorack 은 자체 호스팅 인프라가 실제로 동작하는 방식을 그대로 반영한 몇 가지
기본 요소로 홈랩을 모델링합니다. 이것만 이해하면 나머지는 자연스럽게 따라옵니다.

## 2축 노드 모델

모든 노드는 서로 독립적인 두 축을 가집니다:

- **인프라 타입** — `host`, `vm`, `container`, `k8s_cluster`, `k8s_namespace`,
  `router` 등. 그것이 *무엇인지*를 나타내며, [정해진
  어휘](/ko/docs/nodes/)에서 고릅니다. 타입이 상세 패널에 어떤 필드를 보여줄지
  결정하기 때문에, 아무도 알아보지 못하는 타입은 오류가 아니라 **빈 패널**을
  만들어 냅니다.
- 0개 이상의 **소프트웨어 부착** — Proxmox VE, PostgreSQL, Jellyfin, … — 그 위에서
  *무엇이 도는지*.

상세 필드와 모니터링 슬롯은 **두 축에 걸쳐 병합됩니다.** 예를 들어 Proxmox 호스트는
인프라 타입에서 오는 호스트 수준 필드와 소프트웨어 부착에서 오는 PVE 전용 필드를
같은 패널에 함께 보여줍니다.

## 토폴로지 + 타입이 있는 엣지

인벤토리 *자체가* 그래프입니다. 캔버스에서 노드를 직접 만들고, 이름을 바꾸고,
부모를 옮기고, 연결하면서 **타입이 있는 엣지**를 그립니다. 레이아웃은
[dagre](https://github.com/dagrejs/dagre)가 자동으로 관리하므로 겉모습만 바꾸는
편집이 그림을 뒤섞는 일이 없습니다 — 부모를 옮기거나 엣지를 그리면 그래프가 알아서
다시 흐릅니다.

## 축별 모니터링

각 축은 **프로브 하나**를 가집니다. 인프라 축에서는 도달성 프로브를, 소프트웨어
축에서는 Proxmox API 프로브를 동시에 돌릴 수 있습니다.

두 축 이상이 보고할 때는 **StatusLine** 이 노드의 상태를 결정할 주 축을 고르고,
축을 전환할 수 있는 알약 모양 줄을 함께 보여줍니다. 프로브가 하나도 없는 노드는
아예 건드리지 않으므로, 수동 상태와 자동 상태가 충돌하지 않습니다.

### "감시 안 함" 은 "판정 못 함" 이 아니다

이 둘은 서로 다른 사실이고, UI 도 그렇게 표시합니다:

| 표시 | 뜻 |
| --- | --- |
| **not monitored** | 어느 축에도 프로브가 없습니다. 아무것도 묻지 않았습니다. |
| `unknown` | 프로브가 돌았지만 판정하지 못했습니다 — 타임아웃, 403, 또는 실행 기록이 정리되어 사라진 작업. |

전에는 이 둘이 똑같이 그려졌는데, 이건 들리는 것보다 나쁩니다. 대부분의 노드가
회색인 지도에서는 색이 정보를 잃고, 장애가 늘 보던 배경처럼 보이기 시작합니다.
**not monitored** 로 읽히는 노드는 감시 범위의 구멍이고, `unknown` 으로 읽히는
노드는 들여다봐야 할 프로브입니다.

`monitored` 는 노드 자신의 프로브 설정에서 파생되며 저장되지 않습니다. 그래서
나중에 프로브를 추가해도 낡은 값이 남지 않습니다. 의도적으로 비워 둔 경우라면 동기화
쪽에서 [`meta.probeSkipped`](/ko/docs/nodes/#동기화가-쓰는-키) 로 이유를 남길 수
있습니다.

:::note
상태는 수집기 소유입니다. "이걸 초록으로 해 둬" 같은 수동 설정은 없습니다 —
감시하지 않는 노드는 손으로 넣은 낡은 값을 보여주는 대신 감시하지 않는다고 말합니다.
:::

## 점검 모드

노드(그리고 그 하위 트리)를 점검 중으로 표시하면 수집기가 건너뛰므로, 의도한 중단이
장애로 읽히지 않습니다. 노드는 오류 상태 대신 별도의 점검 중 표시를 보여줍니다.

## 런북

런북은 노드에 연결된 마크다운 문서입니다. 앱 안에서 렌더링되며, 분할 화면 편집기,
`[[node:…]]` / `[[runbook:…]]` 상호 링크, 선택적 git 동기화, 파일 첨부를 포함합니다.
런북에서 관련 노드를 볼 수 있고, 노드 상세 패널에서 그 노드의 런북으로 바로 갈 수
있습니다.
