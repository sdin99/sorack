웹 UI 가 하는 모든 일은 `/api/*` 를 거칩니다. 스크립트도 API 키로 같은 일을 할 수
있고, 리컨실러나 동기화 작업처럼 **브라우저 앞의 사람이 아닌 것**에는 그게 맞는
방법입니다.

## 키 발급

설정 → **API keys** → *New key*. 범위를 고르고, 6개월 뒤에도 알아볼 수 있는 이름을
붙이고, 값을 복사하십시오 — 값은 `sha256(key + AUTH_SECRET)` 으로 저장되며 다시 볼 수
없습니다.

키는 로그인된 세션에서만 발급됩니다. 키는 다른 키를 만들거나 폐기할 수 없습니다.
그러지 않으면 **내가 알고 있는 키를 폐기해도 접근이 실제로는 폐기되지 않기** 때문입니다.

## 보내기

```bash
curl -H "Authorization: Bearer $SORACK_API_KEY" \
     https://sorack.example.com/api/inventory
```

## 범위

| 범위 | 할 수 있는 일 |
|---|---|
| `read` | `GET`, `HEAD`, `OPTIONS` |
| `write` | api 가 노출하는 모든 것 |

가드는 라우트 목록이 아니라 **HTTP 메서드**를 기준으로 동작하므로, 나중에 추가된
라우트는 아무도 기억해서 추가하지 않아도 함께 보호됩니다.

`POST /api/nodes/:id/probe/test` 는 저장되는 것을 아무것도 바꾸지 않지만 `write` 가
필요합니다. 운영자가 준 주소로 연결을 여는 동작이고, 읽기 전용 키가 촉발할 수 있어야
하는 일이 아니기 때문입니다.

## 두 실패를 구분하기

```
401  {"error":"unauthorized"}
403  {"error":"this API key is read-only","scope":"read"}
```

`401` 은 키가 없거나, 형식이 잘못됐거나, 폐기됐다는 뜻입니다 — 새로 발급하십시오.
`403` 은 키는 유효하지만 이 동작이 허용되지 않는다는 뜻입니다 — 설정을 고치십시오. 둘
다에 대해 재시도하는 클라이언트는 **두 번째에서 영원히 루프를 돕니다.** 재시도 전에
상태 코드로 분기하십시오.

## 요청이 애초에 도착하는지 확인하기

검증에 성공할 때마다 `lastUsedAt` 이 기록되고, 설정 화면에서 키 옆에 표시됩니다. 방금
연결한 키가 여전히 *never used* 로 읽히면, 요청이 sorack 에 닿지 않고 **앞단의 무언가가
응답하고 있는** 것입니다. 인증 프록시가 로그인 페이지를 `200` 으로 돌려주는 것이 흔한
원인이고, 대부분의 클라이언트에게는 이것이 정상적인 요청처럼 보입니다.

## 노드에 소프트웨어 붙이기

호스트나 VM 에서 도는 소프트웨어는 노드가 아닙니다. 그것이 도는 노드 아래에
`meta.software`(어떤 id 들이 있는지)와 `meta.softwareProbes`(각각을 어떻게 확인하는지)로
존재합니다. 둘 다 그 노드 자신의 `PATCH` 를 거칩니다:

```bash
curl -X PATCH .../api/nodes/k8s-master -H 'content-type: application/json' -d '{
  "meta": {
    "software": ["containerd", "kubelet", "cnpg"],
    "softwareProbes": { "cnpg": { "type": "tcp", "host": "10.0.0.10", "port": 5432 } }
  }
}'
```

`meta` 는 교체가 아니라 병합되므로, 한 키를 건드리는 `PATCH` 는 나머지를 그대로 둡니다.
스크립트에 중요한 예외가 두 개 있습니다:

- **`meta.software` 는 배열이고 통째로 교체됩니다.** 그것은 목록 자체이며, 목록에
  더하는 것이 아닙니다.
- **`software` 를 보내면 거기에 없는 것들의 프로브가 삭제됩니다.** 이것은 의도된
  동작입니다 — UI 에서 소프트웨어 체크를 해제했을 때 그 프로브와 수집된 메트릭이 영원히
  남아 있으면 안 되니까요 — 하지만 그 결과 **소프트웨어마다 한 번씩 `PATCH` 하면
  누적되지 않습니다.** 실측: `{"software":["containerd"],…}` 뒤에
  `{"software":["kubelet"],…}` 를 보내면 오류 없이 `kubelet` 만 남습니다.

그러므로 **한 노드의 모든 소프트웨어를 완전한 목록으로 한 번의 `PATCH` 에 담아
보내십시오.**

`meta.observed.*` 는 수집기 소유이고 쓰기마다 데이터베이스 쪽 값이 유지되므로, 호출자가
덮어쓸 수 없고 되돌려 보낼 필요도 없습니다.

## 호출자를 위한 메모

- 키는 만료되지 않습니다. 폐기가 유일한 출구이고, 그래서 `lastUsedAt` 이 있습니다 —
  지우기 전에 확인하십시오.
- 검증 오류는 `400` 이고 필드 이름을 알려 줍니다. `409` 는 중복이라는 뜻이며, 노드는
  id, 엣지는 `(source, target, type)` 세 쌍입니다.
- "API tokens" 에서 이름을 바꾸기 전에 발급된 키는 `sorack_key_` 가 아니라
  `sorack_pat_` 로 시작합니다. 둘 다 받아들이지만 발급되는 것은 후자뿐입니다.
