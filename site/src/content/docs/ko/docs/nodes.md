노드는 `type` 하나와 `meta` 라는 가방을 가집니다. 둘 다 계약입니다. 타입은 상세
패널이 어떤 필드를 그릴지 결정하고, `meta` 는 사용자와 수집기, 그리고 인벤토리를
동기화해 넣는 무언가가 함께 쓰는 공간입니다. 이 페이지는 그 둘의 레퍼런스이며,
[`/api/nodes`](/ko/docs/api/) 로 POST 하는 것을 만들고 있다면 특히 쓸모가 있습니다.

## 타입 어휘

`type` 은 닫힌 목록에 대해 검증됩니다. v0.1.12 까지는 자유 문자열이었고, 그것을
닫게 만든 실패는 알아 둘 만합니다. 이 페이지가 존재하는 이유가 바로 그것이기
때문입니다: 어떤 동기화가 자기 나름의 단어 — `app`, `ingress` — 를 보냈고, 노드들은
일반 아이콘과 **필드가 하나도 없는 상세 패널**로 떨어졌습니다. 렌더러가 그런 키가
없는 표에서 타입을 찾기 때문입니다. 아무것도 오류를 내지 않았습니다. 유일한 증상은
화면에 있었습니다.

| `type` | 무엇을 위한 것인가 | 기본 프로브 |
| --- | --- | --- |
| `host` | 물리 장비 또는 베어메탈 머신. | `system` |
| `vm` | 하이퍼바이저 위의 가상 머신. | `system` |
| `container` | OS 수준 컨테이너(예: LXC). | `system` |
| `router` | LAN 과 인터넷 사이의 게이트웨이. | `tcp` |
| `k8s_cluster` | 쿠버네티스 클러스터. | `k8s` |
| `k8s_namespace` | 워크로드를 묶는 네임스페이스. | `k8s` |
| `k8s_service` | Pod 를 노출하는 Service. | `k8s` |
| `k8s_pvc` | PersistentVolumeClaim. | `k8s` |
| `k8s_cronjob` | 예약 배치 작업. | `k8s` |
| `external_service` | 우리가 의존하지만 우리가 운영하지 않는 것. | `http` |
| `hosted_app` | 우리 것이고 우리가 배포했지만 남의 플랫폼에서 도는 것. | `http` |
| `share` | 네트워크 파일 공유(NFS, SMB). | `tcp` |

짧은 형태 네 개는 받아들여져 정식 타입으로 해석됩니다: `ct` → `container`, `ns` →
`k8s_namespace`, `pvc` → `k8s_pvc`, `svc` → `k8s_service`. 이들은 별개의 타입이
아니라 별칭이며, 상세 패널과 선택기는 정식 카드를 보여줍니다.

그 밖의 값은 허용되는 타입 목록을 담은 메시지와 함께 400 으로 거부됩니다.

### 헷갈리기 쉬운 두 쌍

**`external_service` 대 `hosted_app`.** 기준은 *우리가 고칠 수 있는가*이지, 어디서
도는가가 아닙니다. 우리가 배포하고 패치하는 함수는 남의 플랫폼이 돌리더라도
`hosted_app` 이고, 그 아래의 플랫폼이 `external_service` 입니다. 외부 서비스를
`host` 로 타이핑하면 우리 장비들 사이에 끼워 넣는 셈이 되고 `ip`, `os`, `kernel`,
`uptime` 이 영구히 빈칸으로 남습니다 — **빈 필드는 잘못된 타입이 스스로를 드러내는
방식입니다.**

**`k8s_service` 대 `k8s_cronjob`.** CronJob 에는 clusterIP 도, 포트도, selector 도,
엔드포인트도 없으므로 Service 카드는 CronJob 에 대해 아무것도 설명하지 못합니다.
CronJob 카드는 대신 `schedule`, `lastScheduleTime`, `lastSuccessfulTime`,
`lastStatus`, `suspend` 를 담으며, [판정하지 않고
보고합니다](/ko/docs/adapters/#쿠버네티스).

## `meta`

`meta` 는 자유 형식 객체이고, 그 안의 키는 **누가 쓰는지**에 따라 세 무리로
나뉩니다. 이 구분이 핵심입니다. 하나의 사실에 두 명의 소유자가 있으면 갈라지고,
둘 중 더 오래된 쪽이 무작위로 이깁니다.

| 무리 | 쓰는 주체 | 예시 키 |
| --- | --- | --- |
| 사용자 필드 | 사용자. UI 또는 API | `role`, `ip`, `provider`, `software` |
| 관측값 | 수집기. 매 사이클마다 | `observed.*` 아래 전부 |
| 동기화 주석 | 인벤토리를 동기화해 넣는 무언가 | `syncedBy`, `probeSkipped`, `adr` |

들어오는 길에 두 규칙이 적용되며, `POST` 와 `PATCH` 양쪽에 똑같이 적용됩니다:

- **`null` 은 "이 키를 지워라" 입니다** — null 을 저장하라는 뜻이 아닙니다. UI 는
  필드를 비우려고 이걸 보내고, 동기화는 "이번에는 이유 없음" 을 말하려고 보냅니다.
  null 을 그대로 저장하면 아무도 읽지 않지만 모두가 넘어가야 하는 사실이 남습니다 —
  그리고 null 과 없는 키는 화면에서 똑같이 보이므로, 유일하게 눈에 보이는 증상은
  `meta` 가 천천히 부풀어 오르는 것이었습니다.
- **`observed` 는 거부됩니다.** 수집기 소유이기 때문입니다. 그러지 않으면 호출자가
  아무도 관측하지 않은 관측값을 노드에 심을 수 있고, 프로브가 없는 노드에서는 그것이
  영원히 교정되지 않습니다.

`PATCH` 는 덮어쓰지 않고 병합하므로 바꾸는 키만 보내면 됩니다. 병합의 깊이가 키마다
다르다는 점은 동기화를 만들기 전에 알아 두는 게 좋습니다:

| 키 | `PATCH` 시 |
| --- | --- |
| `manual`, `softwareProbes` | 한 단계 더 깊이 병합 — 형제 항목이 살아남습니다. |
| `observed` | 무시하고 저장된 가방을 유지합니다. |
| 그 밖의 전부 | 최상위에서 통째로 교체합니다. |

따라서 `{"meta":{"manual":{"ip":"10.0.0.2"}}}` 는 `ip` 만 바꾸고 나머지 manual 필드는
그대로 두지만, `{"meta":{"adr":[…]}}` 는 배열 전체를 교체합니다.

`POST` 와 `PATCH` 는 모두 저장된 필드와 함께 파생된 `monitored` 불리언을 돌려줍니다.

### 동기화가 쓰는 키

세 개의 키는, 외부의 진실 원천을 바탕으로 노드를 유지하는 무언가가 UI 에서 스스로를
설명할 수 있도록 존재합니다. 셋 다 선택 사항이고, 셋 다 평범한 `meta` 키입니다 —
손으로 넣는 것을 막는 것은 없습니다.

`syncedBy` — 이 노드를 쓴 주체의 이름 문자열.

```jsonc
{ "meta": { "syncedBy": "inventory-sync" } }
```

상세 패널은 그것이 쓴 값들 옆에 *from inventory-sync* 를 보여주고, 여기서 편집한
내용은 다음 실행에서 교체될 수 있다는 툴팁을 붙입니다. 표현은 의도된 것입니다. 이
필드들은 **계속 편집 가능**하므로 "바꿀 수 없다" 고 말하면 거짓이 되고, 운영자는 그
사실을 나쁜 방식으로 알게 됩니다.

`probeSkipped` — 이 노드에 프로브가 없는 이유를 적는 문자열.

```jsonc
{ "meta": { "probeSkipped": "앞단이 인증 프록시라 200 은 프록시의 응답이다" } }
```

[**not monitored**](/ko/docs/concepts/#감시-안-함-은-판정-못-함-이-아니다) 는 아주
다른 두 상황을 함께 덮습니다. 아직 아무도 손대지 않은 것과, 여기서 프로브를 돌리면
거짓말을 하게 되는 것. 이 키가 그 둘을 가릅니다. *not monitored* 라벨 옆에서만
렌더링되며 다른 곳에서는 나오지 않습니다 — 실제로 감시되는 노드는 이 값을 절대
보여주지 않습니다.

`adr` — 이 노드가 왜 여기 있는지에 대한 결정 기록 배열.

```jsonc
{
  "meta": {
    "adr": [
      { "id": "ADR-014", "title": "앱마다 네임스페이스 하나", "url": "https://…" }
    ]
  }
}
```

`id` 는 필수입니다. `title` 은 없으면 `id` 로 대체되고, `url` 은 `http(s)` 일 때만
링크로 렌더링됩니다 — 죽은 앵커는 결정이 한 번의 클릭 거리에 있다고 주장하지만 사실이
아니며, 이런 기록을 담은 저장소는 대개 비공개입니다.

**링크만** 두는 것은 의도적입니다. 근거 자체를 적을 필드는 sorack 에 없습니다. 결정은
그것을 소유하고 리뷰하는 저장소에 있어야 하고, 여기에 텍스트 상자를 두면 같은 사실의
두 번째 집이 생깁니다.

목록이 비면 이 구역은 스스로를 숨깁니다. 빈 "관련 결정" 제목을 보여주는 대신에요 —
그건 *없다* 로 읽히는데, 실제로는 거의 항상 **아직 아무도 연결하지 않았다**는 뜻이기
때문입니다.

:::note
앱이 알아보지 못하는 키는 그대로 저장되고 그대로 돌려줍니다. 그것이 `meta` 를 자기
데이터를 걸어 두는 곳으로 쓸 수 있게 만드는 성질입니다 — 하지만 동시에 **오타가
오류가 되지 않는다**는 뜻이기도 하니, 처음 쓴 뒤에는 상세 패널을 한 번 확인하십시오.
:::
